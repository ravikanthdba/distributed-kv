Distributed-kv Pending issues list

🐞 Issues Identified (No Descriptions, Just List)
	1.	Existing data is not replicated to newly joined nodes.
	2.	No automatic peer discovery — requires manual /join API call.
	3.	No gossip protocol or failure detection for peer liveness.
	4.	Peer removal is not implemented — no /leave or health expiry.
	5.	Replication is fire-and-forget — no quorum / consensus logic.
	6.	No versioning or conflict resolution for concurrent writes.
	7.	Read from local store only — no fallback to peers.
	8.	No sharding or partitioning — all nodes replicate all keys.
	9.	No durability — data is stored only in-memory (not persisted).
	10.	No consistency model — eventual vs strong not defined.
	11.	No authentication or authorization between nodes.
	12.	No encryption (TLS) in peer-to-peer communication.
	13.	No metrics or observability (logs only, no Prometheus, etc.).
	14.	No data compaction or GC.
	15.	No support for snapshotting or backups.
	16.	No rate limiting or load shedding.
	17.	No backpressure handling in replication fan-out.
	18.	No write-ahead logging (WAL) for recovery.
	19.	No leadership election (no Raft or similar yet).
	20.	No clock synchronization (NTP) to resolve timestamp-based logic.
	21.	No protection from split brain or duplicate cluster formation.
	22.	Testing support is missing (unit, integration, chaos).
	23.	No multi-tenancy or namespacing.
	24.	No audit logging for key access history.
